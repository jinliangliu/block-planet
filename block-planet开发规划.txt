# 儿童像素沙盒游戏block-planet开发规划（Godot / Android）

## 1. 项目概览

### 1.1 核心定位
- **面向儿童**：操作简单、UI 大而清晰、色彩鲜艳、怪物可爱化、无恐怖元素。
- **核心玩法**：体素世界自由建造、探索、生存与红石电路。
- **双模式**：
  - **生存模式**：采集资源、管理饥饿值、躲避/对抗怪物、从零建造庇护所。
  - **创造模式**：无限方块、飞行、专注建筑与红石工程。

### 1.2 平台与引擎
- **引擎**：Godot 4.x（建议 4.3+，支持 Mobile 渲染器）。
- **语言**：GDScript（开发效率高，性能足够，关键瓶颈可用 C# 或 GDExtension 优化）。
- **目标设备**：中低端 Android 手机/平板，目标 30~60 FPS。

---

## 2. 核心玩法设计

### 2.1 世界与方块
- **方块**：草方块、泥土、石头、木头、树叶、沙子、矿石、玻璃、水、岩浆等。
- **方块属性**：
  - 硬度（破坏时间）
  - 是否透明（玻璃、树叶）
  - 是否可碰撞
  - 是否可放置（如红石粉）
  - 纹理（使用纹理图集）
- **世界生成**：使用 `FastNoiseLite` 生成地形，包含平原、山地、树木、矿洞、水域。

### 2.2 生存模式
- **生命值**：10 颗心，受跌落、怪物攻击、饥饿伤害。
- **饥饿值**：0~20，随时间与活动消耗；饥饿值过低时无法奔跑，为零时持续掉血（简单模式可关闭）。
- **资源采集**：徒手或工具破坏方块获得掉落物。
- **工具与耐久**：木、石、铁、钻石等级；工具耐久消耗，损坏后消失。
- **合成系统**：基础合成 + 工作台合成，图形化配方，适合儿童。
- **昼夜循环**：白天 10 分钟，夜晚 5 分钟；夜晚生成怪物，可用床跳过夜晚。
- **怪物**：
  - 可爱化设计：小僵尸、小骷髅、小蜘蛛等。
  - AI：白天躲避阳光，夜晚主动靠近玩家。
  - 掉落物：用于合成或食物。
- **庇护所**：玩家通过放置方块建造房屋，阻挡怪物。

### 2.3 创造模式
- **无限资源**：物品栏直接选择所有方块和物品，放置不消耗。
- **飞行**：双击跳跃切换飞行/步行；飞行时上下移动，无重力。
- **无敌**：不受伤害，饥饿值不消耗。
- **红石工程**：
  - 红石粉：传播信号，最多 15 格，信号衰减。
  - 电源：红石火把、按钮、拉杆、压力板。
  - 执行器：红石灯、门、活塞、TNT、音符盒等。
  - 中继器：延迟与信号增强。
  - 更新机制：使用队列 + 延迟更新，避免递归过深。

## 3. Godot 技术架构

### 3.1 项目目录结构建议
res://
├── scenes/ # 场景文件
│ ├── main.tscn
│ ├── player.tscn
│ ├── chunk.tscn
│ ├── ui/
│ └── mobs/
├── scripts/
│ ├── world/ # 世界生成、区块管理
│ ├── player/ # 玩家控制、生存状态
│ ├── ui/ # 背包、合成、快捷栏、设置
│ ├── systems/ # 存档、红石、合成、昼夜
│ ├── mobs/ # 怪物AI
│ └── core/ # 全局管理器、事件总线
├── assets/
│ ├── textures/ # 方块纹理图集、UI 图标
│ ├── sounds/ # 音效
│ ├── fonts/ # 像素字体
│ └── models/ # 简单模型（可选）
└── shaders/ # 自定义着色器（可选）

### 3.2 体素渲染（核心）
- **区块大小**：建议 `16 × 256 × 16`（宽×高×深），或根据性能调整为 `16 × 128 × 16`。
- **渲染方法**：
  - 使用 `ArrayMesh` 动态构建每个区块的网格。
  - 遍历区块内所有方块，只生成可见面（相邻方块透明/不存在时）。
  - 使用纹理图集，一个材质 + UV 偏移实现所有方块纹理。
- **碰撞**：
  - 每个区块生成一个 `StaticBody3D` + `CollisionShape3D`。
  - 使用 `ConcavePolygonShape3D` 从网格创建碰撞。
  - 可选：为移动端优化，将碰撞体简化为只包含表面方块。
- **纹理过滤**：设置 `Filter` 为 **Nearest**，保持像素风格。

### 3.3 区块管理
- **动态加载**：以玩家为中心，加载半径 6~8 个区块。
- **异步生成**：使用 `WorkerThreadPool` 或 `Thread` 在后台生成网格数据，主线程提交 `ArrayMesh`。
- **卸载**：超出半径的区块保存数据并释放内存。
- **修改追踪**：记录被玩家修改的区块，用于存档。

### 3.4 玩家控制
- **移动**：`CharacterBody3D`，重力、跳跃、碰撞。
- **触屏输入**：
  - 左侧虚拟摇杆：移动。
  - 右侧滑动：旋转视角。
  - 按钮：跳跃、攻击/破坏、使用/放置、飞行切换（创造模式）。
- **视角**：第一人称或第三人称，建议第一人称便于建造。

### 3.5 存档系统
- **格式**：推荐二进制（或 JSON + gzip），包含：
  - 世界种子
  - 已修改区块的方块数据
  - 玩家位置、背包、生命、饥饿值
  - 当前模式
  - 红石状态
- **位置**：`user://saves/world_01/`。
- **自动保存**：每 30 秒自动保存，退出时保存。

### 3.6 红石系统简化设计
- **信号传播**：
  - 红石粉：信号强度 15，每传播一格减 1。
  - 红石火把/拉杆/按钮：输出信号强度 15。
  - 中继器：将信号恢复为 15，可设置延迟（1~4 tick）。
- **更新队列**：
  - 使用 `Array[RedstoneUpdate]` 队列，按顺序处理信号变化。
  - 每个 tick（0.1 秒）处理一轮更新，避免递归与死循环。
- **执行器**：
  - 红石灯：点亮/熄灭。
  - 门：开/关。
  - 活塞：推动方块（简化：只推动单个方块，不处理连锁）。
  - TNT：激活后延迟爆炸。

## 4. 移动端优化策略

### 4.1 渲染优化
- 使用 **Mobile 渲染器**（Godot 4 中 `Forward Mobile`）。
- 限制绘制距离：默认 6 个区块，可在设置中调整。
- 视锥剔除：仅渲染相机视野内的区块。
- 纹理图集：所有方块一张图集，减少材质数量。
- 禁用实时阴影或使用低分辨率阴影。

### 4.2 内存优化
- 区块数据使用紧凑格式（如 `PackedByteArray` 存储方块 ID）。
- 及时释放未使用区块的网格和碰撞体。
- 纹理和音频资源使用 `.import` 压缩。

### 4.3 性能优化
- 区块网格生成放在后台线程，避免卡顿。
- 使用对象池管理怪物、粒子效果。
- 减少物理计算：大部分方块碰撞由静态碰撞体处理，玩家使用 `CharacterBody3D`。
- 限制同时活跃的怪物数量（如 10~15 只）。

## 5. UI/UX 设计

### 5.1 移动端布局
- **快捷栏**：屏幕底部 5~8 格，大图标，点击选择。
- **虚拟摇杆**：左下角，半透明。
- **视角滑动**：屏幕右侧任意区域滑动。
- **动作按钮**：右下角，跳跃、攻击/破坏、放置/使用。
- **背包/合成界面**：全屏弹窗，大格子，拖拽或点击移动物品。

### 5.2 儿童友好设计
- **像素风格**：鲜艳、圆润，避免暗黑。
- **引导教程**：第一次进入生存模式时，通过任务提示教会采集、合成、建造。
- **反馈**：放置/破坏方块有音效和粒子效果。
- **安全模式**：可选“和平模式”，怪物不攻击玩家，饥饿值不消耗。

## 6. 开发路线图（单人全职估算）

| 阶段 | 内容 | 预计时间 |
|------|------|----------|
| **M1 基础框架** | 项目搭建、玩家移动、摄像机、基础 UI | 1~2 周 |
| **M2 方块与区块渲染** | 方块注册、区块生成、网格构建、纹理图集 | 2~3 周 |
| **M3 世界生成** | 地形噪声、树木/矿洞生成、区块流式加载 | 2~3 周 |
| **M4 交互系统** | 方块放置/破坏、碰撞、快捷栏、背包 | 2~3 周 |
| **M5 生存系统** | 生命/饥饿、合成、工具耐久、物品掉落 | 3~4 周 |
| **M6 怪物 AI** | 怪物生成、移动、攻击、昼夜行为 | 3~4 周 |
| **M7 创造模式** | 无限资源、飞行、无敌、模式切换 | 1~2 周 |
| **M8 红石系统** | 红石粉、电源、执行器、更新队列 | 3~4 周 |
| **M9 UI/UX 完善** | 触屏适配、教程、设置、音效 | 2~3 周 |
| **M10 优化与测试** | 性能优化、设备兼容、Bug 修复、儿童测试 | 3~4 周 |
| **M11 发布准备** | 打包 APK、商店素材、隐私政策、测试分发 | 1~2 周 |

**总计：约 5~7 个月**（根据个人经验和投入时间浮动）。

## 7. 关键风险与应对

| 风险 | 应对 |
|------|------|
| **移动端性能不足** | 降低区块加载半径、简化网格、使用 Mobile 渲染器、限制怪物数量。 |
| **体素渲染卡顿** | 后台线程生成网格，主线程只提交；优化面剔除算法。 |
| **红石系统复杂度过高** | 先实现基础红石粉 + 红石火把 + 门/灯，后续迭代扩展。 |
| **存档文件过大** | 仅保存被修改区块，使用二进制压缩。 |
| **触屏操作不便** | 反复测试调整按钮大小与布局，提供灵敏度设置。 |

## 8. 发布与合规建议

- **包体**：使用 Godot 导出 Android APK/AAB，注意纹理压缩（ETC2/ASTC）。
- **权限**：仅请求存储权限（保存存档），无网络权限（离线游戏）。
- **隐私**：不收集任何儿童个人信息，符合 COPPA/GDPR-K 要求。
- **内容分级**：确保无血腥、恐怖元素，怪物可爱化。

---

## 9. 单机离线补充约定

- **定位**：单机离线版，暂不包含任何联网、联机、排行榜、云存档或网络功能。
- **权限**：不申请网络权限；仅申请本地存储权限，用于保存离线存档。
- **数据**：所有存档保存在本地 `user://saves/`，不上传任何数据，符合儿童隐私要求。
