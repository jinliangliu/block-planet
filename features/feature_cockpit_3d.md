## 0. 结论（先读这段）

**推荐路线 B「分层座舱」：3D 环绕内装（框 + 仪表台 + 椅背）+ 2D 精读面板保持不动**，分四层递进交付，先做 L1+L2（本轮可交付），L3 视效果定，L4（3D 热点交互）**明确不做**。

| 路线 | 一句话 | 结论 |
|---|---|---|
| A 维持现状 | 座舱纯 2D，接受「环顾框不动、低头无物」 | 否。这是对比评审认定的最高优先级结构性差距 |
| **B 分层座舱** | **3D 环绕内装随视线，2D 精读面板守尺寸纪律** | **推荐**。低成本贴合本作约束，两处缺陷各有对症修法 |
| C 完整 3D 座舱 | 战雷式全建模 + 交互热点 + 飞行员模型 | 否。成本/触屏精细操作/儿童向三重不匹配（§3） |

B 路线的核心分工：**3D 层回答「我坐在哪」（空间感、环顾视差、低头有物），2D 层回答「飞机什么状态」（精读，已经过 D-049~D-053 五轮打磨 + 用户亲自定尺寸）**。两者吃同一份 `FlightInstruments` 读数——本作既有差异化「单一数据链路、多视图永远一致」直接继承，不会出现 IF 社区抱怨的「虚拟仪表与 HUD 数据脱节」。

## 1. 主流 3D 飞行游戏座舱设计调研

### 1.1 战雷（War Thunder）——本作 2D 座舱的风格来源

- **按史实全建模**：「从每一个传感器、开关到控制杆的每一个细节」都建模；座舱内自由视角环视；仪表盘大部分设备正常显示；**有飞行员模型**（飞行中能看到手和脚操作节流阀与摇杆）——这是战雷座舱沉浸感的标志件。
- **成本真相**（官方开发博客，update 1.65）：为多座机引入座舱时用的是「简化座舱」策略——a simplified cockpit that takes real aircraft topography into account, pilot allocation and provides a sufficient set of instruments to fly。官方原话：**造一个轰炸机的完整座舱 ≈ 造一整架战斗机的时间**；给所有轰炸机做全座舱 ≈ 新增一整个国家的航空树。
- **CDK 规范工程量**：单座 70-150K 三角形、双座 100-200K；相机需支持座舱内 20-30 cm 范围移动；杆/舵/油门/襟翼/起落架等每个可动物体都要有命名动画。
- **对本作的意义**：连战雷自己都为多座机走简化座舱；本作是「一架通用轻型机 + 蓝图拼装机」，简化座舱不是妥协而是行业常规操作。

### 1.2 MSFS 2020/2024 —— 6DoF 与清晰度

- **6DoF 头部追踪**（TrackIR/Tobii 官方 spotlight）：yaw/pitch/roll + XYZ 平移——lean forward 看仪表、shift sideways 绕过风挡支柱、look into a turn。相机不再锁死正前。
- **VR 交互重构**（Asobo，PS VR2 更新）：6DoF 控制器「亲手」操作每个装置，拨开关有金属阻尼振动；配套三项清晰度技术——**注视点渲染**（80% 资源集中注视区）、**可调节缩放光栅化**（拉近看仪表自动提升局部分辨率）、**帧复制**（双眼延迟 <10 ms）。
- **六仪表布局**（教学共识）：顶排 空速/姿态/高度，底排 转弯协调/航向/垂直速度——即本作座舱六件套的同款排布，「scanned without a large head movement」。
- **对本作的意义**：6DoF 是「环顾有物」的前提（本作已有自由观察视角，缺的是随动的几何）；「拉近看仪表要清晰」支持「2D 精读层 + 3D 世界层」分工——屏幕上的 2D 簇就是永久清晰的「注视点渲染」。

### 1.3 Infinite Flight —— 移动端标杆（最相关的同侪）

- **座舱演进路径**（官方博客）：2018 A-10 首个可用仪表（working gauges）→ 19.2 XCub 玻璃座舱与可用开关（Garmin G5/G3x）→ 26.4 A321neo 交互座舱 + MCDU。官方原话：先做 first iterations with limited features and functionality，**随设备性能逐步加功能**。
- **主信息放 HUD**：Fly Screen 的 HUD 承载速度/高度/姿态主要信息 + 小地图 + 可定制底部状态栏；虚拟座舱是「低头细看」的补充而非唯一信息源。
- **社区实证**（官方论坛 2025-02「Inside the Virtual Cockpit」）：① 虚拟仪表与 HUD 数据可能脱节；② 触屏精细操作难——「想缩放调油门/开关」；③ 热议「dual-mode cockpit：简化视图 + 高级交互」；④ 有用户明说 x-plane mobile 的强交互 sucks having to be so careful about every little touch。
- **对本作的意义**：移动端飞行 sim 的成熟形态 = **HUD/2D 层管状态、3D 座舱管空间感**；强交互在触屏上口碑差，儿童向尤其灾难——这正是 L4 不做的直接依据。

### 1.4 座舱仪表可读性研究（人因，跨游戏通用）

- **T-arrangement 与扫描模式**（固定基模拟器眼动研究）：眼睛应回到一个关键仪表（姿态仪）后再参考次级源；把 gaze 均匀分布在多个信息源是最差模式；**空间布局应把主仪表放中心位置**引导扫描回中。
- **Gestalt / 接近性兼容**（FAA 多屏显示设计指南引述）：仪表按关键性/使用频率/使用序列聚类；同色系直至少数警告色跳出（emergent features）；高对比、去 clutter。
- **对本作的意义**：D-052 圆盘化 + D-053 主表居中的排布已符合这些原则；3D 化改造**不得破坏既有布局语义**（尺寸纪律见 §5 红线）。

## 2. 本作现状与约束（方案的事实基础）

> **D-065 已实施 L1+L2+L3，本节下面的「现状」是立项时（D-050~D-053 时代）的快照**，
> 与现行代码的差异已在每条后标注「→ 现行」。现行事实以 `feature_flight.md` §7 与
> `docs/decisions.md` D-065 为准。

原现状（立项时）：

- **座舱无内装几何**：第一人称 = 隐藏整机外观（D-050 内视开关）+ 相机进机身 + 全屏 2D `CockpitInstruments`（框体/dash/六件仪表/磨损全像素画）。
  → 现行：`CockpitInterior`（39 盒 / 9 共享材质）提供 3D 内装，与 2D 像素层**叠加**。
- **必然结果（非 bug）**：环顾时框不动（2D 层不参与 3D 相机）、低头无物。
  → 现行：环顾有视差、低头看到仪表台 + 杆手；正视时 2D 簇仍是权威读数层。
- **已有 3D 资产**：`CockpitPanel`（SubViewport 1024×640 → ViewportTexture 贴 3D 平面，位于 (0,−0.35,−1.7)、上仰 25°、自发光）——低头可见，但第一人称下被隐藏（读数由 2D 簇接管）。
  → 现行：`768×168 @ 30 Hz` 不透明 + `unshaded + albedo`（不再走 emission），`PANEL_W/H = 0.98 × 0.215 m`、`PANEL_POS (0, 0.75, −4.15)`、`PANEL_TILT_DEG −27.8`；**第一人称即显示**（与 2D 簇重合）。
- **2D 座舱的演进纪律**（§7.8）：D-049 放大被用户打回 → D-051 回缩 → D-052 战雷化 → D-053 盘排 −1/3（用户圈注「缩小」）；**改版不得借「战雷化」把尺寸顶回去**。
  → 现行：纪律不变，D-065 未改动 2D 簇任何尺寸（`cockpit_align_probe` 钉住「2D dash 未变形」）。

约束：

| 约束 | 对座舱设计的含义 |
|---|---|
| 中低端 Android + Mobile 渲染器 | 几何预算苛刻：体素盒几十个 BoxMesh 可接受；70-150K 三角高模不可接受 |
| 儿童向 | 交互必须防误触；IF 社区已实证强交互触屏口碑差 |
| 体素风格 | 盒体几何天然契合，不需要高模贴图 |
| 单一数据链路（`FlightInstruments`） | 3D/2D 共用读数，不会脱节 |
| 蓝图机契约（不建座舱几何） | 内装只上默认机模；蓝图试飞仍无座舱（保持现状） |
| 探针文化 | 几何改动窗口截图目检；无头断言逻辑层 |

## 3. 路线对比与取舍

| 维度 | A 维持 | **B 分层座舱（推荐）** | C 完整 3D |
|---|---|---|---|
| 环顾视差 | 无 | **有**（3D 框随动） | 有 |
| 低头有物 | 无 | **有**（仪表台+椅背+罩内侧面） | 有 |
| 几何/三角形预算 | 0 | 低（数十盒体，可合并） | 高（单座 70-150K，战雷规范） |
| 开发量 | 0 | 中（纯几何，无交互） | 大（建模 + 动画 + 热点） |
| 触屏误触风险 | 无 | 无（不加交互） | 高（IF 社区实证） |
| 2D 簇五轮打磨成果 | 保留 | **保留（尺寸纪律不破）** | 被取代（倒退） |
| 性能可预期性 | — | 盒体 draw call 少，帧预算可控 | Mobile 渲染器压力大 |

**为什么不是 C**：① 成本——战雷官方数据：全座舱 ≈ 一整架飞机的工作量，本作是单人项目节奏；② 触屏——IF 社区对强交互的负面反馈 + 儿童向防误触是硬约束；③ 本作 2D 簇已经过五轮打磨且用户亲自校准尺寸，推倒重做违背既有决策链（D-047/049/051/052/053）。
**为什么不是 A**：对比评审认定的最高优先级结构性差距，且环顾/低头是飞行空间感的核心来源（战雷/MSFS 都把「座舱内环视」作为沉浸感基石）。

## 4. 推荐方案：分层座舱（四层递进，每层独立可交付/可回退）

### L1 座舱环绕框 3D 化（治 U-1「环顾框不动」）——**已实施（D-065，22 盒）**

新建体素盒拼的座舱内装几何（挂 `Aircraft` 节点，随机体 `place()` 落位，D-050 内视模式下显示、此前「隐藏整机外观」逻辑要为其开例外）：

- **风挡框 + 顶檐**：对应 2D 层的 `FRAME_RAIL_H=20` / `PILLAR_TOP_W=44` 语义，做成眼位前方的框体（盒阵列，体素风）。
- **A 柱（风挡支柱）**：左右各一斜边柱——战雷/MSFS 座舱里绕过支柱看世界是空间感的重要来源。
- **侧 console 外框**：2D 侧 console（宽 92）对应的 3D 侧壁，带铆钉/拨杆剪影（盒+小圆柱即可，不强求细节）。
- **地板 + 椅背**：低头即见（治 U-2 的一半）。
- **方向舵踏板**（可选）：两盒 + 随 yaw 输入微动。

不做交互、不改 2D 簇。验收：窗口截图探针（第一人称正视/左视/右视/低头/自由观察各一张）目检视差与遮挡关系。

**实施记录（实际数值，全部眼位相对）**：顶檐 `1.30×0.12×0.26 @ (0, 1.36, −1.15)`、后拱 `@ (0, 1.27, 0.95)`、两根导轨 `0.10×0.10×2.10`、A 柱顶端 `(±0.65, 1.30, −1.15)` → 底端 `(±0.92, −0.57, −0.48)`（截面 `0.052×0.10`）、侧 console `0.26×0.75×1.60 @ (±1.02, −0.95, 0.30)`、地板 `2.30×0.12×2.50`、椅背 `0.62×0.75×0.16 @ (0,−0.50,0.65)`、头枕 `0.34×0.22×0.14 @ (0,−0.10,0.60)`、**后隔板 `4.40×2.48×0.10 @ (0,−0.03,1.10)`**（宽度按 82° 竖直 FOV + 16:9 的水平半角 57° 算出，2.30/3.40 都会在回望时漏天空）、两块踏板 `0.18×0.05×0.28 @ (±0.21,−1.24,−0.80)`。
**A 柱不照抄 2D 的 `PILLAR_TOP_W = 44 px`**：那是屏幕中央附近的装饰性收纳边，照它布柱会让两柱在中线并拢成「Λ」劈开视野（首轮取证 3D 框占了 1/3 屏）。

### L2 仪表台 3D 化（治 U-2「低头无物」）——**已实施（D-065，12 盒 + 面板反转）**

- **仪表台底板**：3D 盒板 + 3D 螺钉/封板/拨杆开关剪影（呼应 2D 层的封板与左 console 拨杆），位于 2D dash 板对应的世界位置。
- **升级现有 `CockpitPanel`**：SubViewport 内容从「七圆+数字条」扩为完整六件套读数（**复用 `cockpit_instruments.gd` 的绘制代码进 SubViewport，不重画**），贴片平面与 2D 簇 dash 区对齐。
- **第一人称 visibility 反转**：现在第一人称隐藏 CockpitPanel（读数由 2D 接管）；L2 起改为**显示**——低头/环顾时看到的就是世界里的仪表台，正视时与 2D 簇重合（对齐后视觉连续）。2D 簇保留为正前方精读层（D-053 尺寸纪律原样不动）。
- 语义分工（借 IF 形态）：2D = 眼前 HUD 式精读；3D = 世界里的仪表台。数据同源，不存在 IF 社区的脱节问题。

**实施记录（实际数值）**：承托板 `DASH_RIM = 0.05` → 板 `(PANEL_W+0.10) × (PANEL_H+0.10) × 0.08 = 1.08×0.315×0.08`，盘面 7 圆 `92×92 @ y=10, x=8+110i`、4 条 LCD `175×48 @ y=108, x=10+191i`；板块 + 上/下暗缝 + 下唇 + 6 螺钉（`0.025` 立方，落在 `PANEL_W/2 + DASH_RIM/2` 的边条中线上）+ 2 根 `0.06×0.77×0.06` 细撑杆 = 12 盒。板顶沿屏幕位置 **549 px > 2D dash 上沿 538.67**，整块板藏进 dash 带内。
**对齐实测**：四角投影目标 TL(373.7,572.1) TR(906.3,572.1) BL(323.7,726.8) BR(956.3,726.8)，实测偏差 **0.2~0.3 px**（+ 软断言 ±12 px）。

### L3 座舱生命感（视 L1/L2 效果定）——**已实施（D-065，5 盒）**

- 操纵杆 + **飞行员的手**（战雷标志件）：一盒杆 + 两手盒，随 pitch/roll/yaw 输入偏转（`_animate_bp_surfaces` 同款驱动）。
- 发动机启动时杆微颤、滑跑时杆随地面颠簸（噪声小幅度）——低成本高沉浸。
- 左 console 拨杆开关 3D 化并与 2D 检查单夹呼应（襟翼/起落架拨杆位置可呼应）。

**实施记录（用户定夺「一只手 + 一根杆」）**：`StickPivot @ (0,−1.31,−0.40)`，杆座 `0.20×0.12×0.20`、杆身 `0.08×0.54×0.08`、握把 `0.13×0.20×0.13`（`STICK_MAX_PITCH/ROLL = 0.22 rad`）、手 `0.16×0.22×0.17`（中心与握把重合、朝飞行员偏 1.5 cm，即真的包住握把）、**小臂 `0.14×0.14×0.42`**（挂 pivot 内，往飞行员方向伸直——没有小臂时低头只看到「地板中央一块悬浮肤色方块」，大脑不认它是自己的手）。踏板行程 `PEDAL_TRAVEL = 0.06`；微颤 `TREMOR_AMP 0.012`（引擎运转）/ `BUMP_AMP 0.03`（滑跑颠簸），噪声频率与 `aircraft_camera._apply_shake` 同组（37.1/71.3/53.7/83.1）。**杆顶高度受 F1 净空门封顶**（眼→面板下沿视线在杆处 0.867，净空 0.221 m），所以"看起来小"靠加粗而非加长解决。

### L4 3D 热点交互（ClickSpot 式）——**明确不做**

- 战雷 CDK 的每个可动物体命名动画、MSFS VR 的 6DoF 控制器亲手操作，都依赖精细指针输入；IF 社区实证触屏强交互「要非常小心每一个触摸」，儿童向是灾难。
- 本作功能需求已由 2D 面板 + 快捷键全覆盖（襟翼一个键循环、起落架、发动机 F、自动改平双击）。
- 若未来桌面端要做，走「桌面专属热点 + 触屏保持 2D」的双轨，不作为座舱缺陷的一部分。

## 5. 红线与回归策略

| 红线 | 来源 |
|---|---|
| 2D 簇尺寸/布局不动（D-053：主表/dash 占屏高 25.2%/14.1%） | §7.8 用户明确要求过一次「缩小」，改版不得顶回去 |
| `FlightInstruments` 契约不改 | 六视图单一数据链路 |
| 蓝图机不建座舱几何 | §7.1 既有契约 |
| 几何改动窗口截图目检（无头查不出） | D-010 探针文化 |
| Mobile 渲染器帧预算：盒体数量与 draw call 需实测 | 中低端 Android 目标 |
| D-050 内视开关语义扩展（内装例外显示）需同步 feature_flight.md §7.1 | 说明书基准 |

回归策略：L1/L2 各配一个窗口截图探针（正视/左/右/低头/环顾五视角 + 蓝图机无座舱断言），入 `run_regression.sh full` 档（日常 headless 不跑截图组）。

## 6. 已定夺（2026-10-22 用户拍板）

1. **本轮做 L1 + L2（+ L3）**：一次交付「环绕框 + 仪表台 3D 化」，L3 杆/手同期完成。
