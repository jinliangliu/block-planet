## 0. 结论（先读这段）

规格可以实施，且大半组件项目已有雏形（区块流式加载 D-035、16×16 水平区块、噪声高度图地形）。**4 个决策点已定夺**（§6，2026-10-21 用户答复）：

1. **速度尺度 → 保持现行**：飞机横跨约 42 分钟（不按规格提速 10 倍）。世界「大」的感知来自地貌变化与里程里程碑，不来自时速表。
2. **世界结构 → 每区域各 128 km**：保留 11 区域地球选择器，不合并为单一世界。
3. **低模实现 → 高度图粗网格**：4×4 格采样 + 4×4 区块合并，不渲染树/结构。
4. **实施范围 → 全量 P0→P3 连续实施**。

推荐路线：**P0 坐标与 origin shifting 地基（✅ 已完成，D-062）→ P1 一格=一米尺度切换（✅ 已完成，D-063）→ P2 双环加载 + 低模 LOD（✅ 已完成，D-064）→ P3 世界边界 + 大洋（✅ 已完成，D-064）→ P4 速度尺度（选 A，仅文档记录）**。每 Phase 独立可回归、可回退，配 ADR。

**P0 已落地内容**（详见 ADR D-062）：`world_to_chunk(Vector3)->Vector2i` / `chunk_to_world(Vector2i)->Vector3` 底层接口；区块键 `Vector3i → Vector2i` 全量迁移；三层坐标契约（世界空间=整数真相 / 渲染空间=世界−origin / 节点持有渲染坐标）；浮动原点（阈值与网格均 4096 格，`World` 节点位置 = −origin）；`WorldAnchor` 注册组（祖先去重）承接 Main 级实体与渲染锚点搬迁；`Events.origin_shifted(delta)` 信号。验证：`tests/world_coord_probe` 27 断言全 PASS（纯函数恒等式含负坐标 / shift 行为 / 真实场景传送 6000 格 / 实体不变式）。

## 2. 四个根本冲突

### 2.1 速度数学（定夺项 ①）

| 目标 | 反推速度 | 相对现状 |
|---|---|---|
| 飞机 4 分钟横跨 128 km | ≈ 533 m/s（约 1900 km/h） | 巡航 50.4 m/s 的 **10.6 倍** |
| 汽车 3 分钟横跨 128 km | ≈ 711 m/s（约 2560 km/h） | 现赛车的 **20 倍以上** |

按 533 m/s 设计的连锁后果：① 飞行模型全部常量 ×10（失速 13.1→131 m/s、VNE 55→550 m/s、解体 Δv 7→70 m/s），D-030~D-035 的「温和飞行」打磨全部作废；② 128 m 高模区只剩 **0.24 秒**预警；③ 每帧位移 8.9 m = 半个多区块，而单块生成 23~29 ms——**流式加载系统永远追不上**（D-035 的时间预算制就是按温和速度设计的）。

三个选项：

- **A 保持现行速度**（推荐）：横跨约 42 分钟（飞机）。世界「大」的感知来自地貌变化、里程里程碑（`aircraft_distance` 事件已有）、飞行指引与任务，不来自时速表。
- **B 按规格提速 ~10×**：飞行玩法重做 + 流式窗口扩大一个数量级（生成吞吐不可能跟上）+ 地形碰撞余量重算。
- **C 折中 ×2~3**：横跨 14~21 分钟，飞行模型部分重调，流式预算要相应放宽。

我的建议：**A**。若日后要「快」，加「巡航加速 / 机场传送」功能，不动物理根基。

### 2.2 世界结构（定夺项 ②）

现状：11 区域 = 11 张独立地图（各自 `seed`/地形 profile/机场/村庄/生物/储物箱，切换 = 重载主场景）。「亚洲」是唯一做了分层地形的区域（D-055）。

- **选项 A「每区域各 128 km」**（改动最小）：保留全部现有系统链路原样，只改世界尺度与加载。大洋区域天然就是「128 km 大洋 + 岛礁 + 冰山」（冰山噪声已存在，D-028）——「横跨大洋」在每个大洋区域里成立。代价：区域之间仍不连续（与现在一样，本来就是切地图）。
- **选项 B「单一 128 km 世界」**（字面实现「把地球装进大盒子」）：需要新做大尺度世界生成——大陆/大洋/山/河在一张连续噪声场里成立；11 个区域 profile 降级为「按位置采样的生物群系预设」；地球 UI 改为总览图/出生点选择；村庄/机场选址规则在新地形上重新保证（平整保护区 `FLAT_FEATHER` 机制可复用）。工作量集中在世界生成，约为 A 的 3~5 倍，且区域卡片「地理知识」的定位要重新解释。

我的建议：**A**。B 的世界生成是独立大课题，值得单开一轮；A 同样给你 128 km 的大海与大陆。

### 2.3 低模渲染区（定夺项 ③：实现方式）

- **A 高度图粗网格**（推荐）：地形是无洞穴高度图（`chunk.gd` 注释即此论断），低模区块 = 4×4 格采样（4 m 分辨率）粗网格 + 生物群系顶点色；4×4 区块合并成一网格控 draw call；无碰撞、无方块数据、不渲染树/结构。玩家在 128 m 外够不着编辑，忽略编辑零损失。
- **B 完整网格画到 256 m**：draw call 1000+，中低端 Android 必爆，仅列作对照。

### 2.4 浮动原点（技术必做，无需定夺，影响面要知情）

float32 距原点 64 km 处量化 ≈ 8 mm——区块节点位置量化令相邻区块共享边错位（裂缝）、相机与物理体抖动。官方 win64 构建为单精度（双精度构建不适合本项目 Android 目标）。

方案：**整数坐标为真相，渲染坐标浮动原点化**——

- 区块/地标/实体的逻辑坐标一律整数（世界空间）；
- `World` 持 `_origin: Vector2i`（格），渲染位置 = 世界位置 − origin；
- 玩家越过阈值（建议 4096 格 = 4 km；该处 float32 量化 0.5 mm，不可见）时 recenter：整体搬迁所有世界锚定节点 + 玩家，逻辑坐标不变；
- 搬迁根：世界锚定节点现分散在 `$World`（区块/结构）、`$MobSpawner`、`$BreakFx` 等——实施第一步是归拢（ShiftRoot 或递归搬迁函数 + 探针断言无漏项）；
- 存档无需迁移：**世界本就不落盘**（无 `user://world` 存档，区块编辑只在内存留存），持久化项（设置/进度/蓝图等）都在原点附近。

## 3. 推荐架构详案

### 3.1 坐标三层与 API

```
世界空间（int，真相）          渲染空间（float，origin-shifted）
world_to_chunk:  Vector3  -> Vector2i   # floor(x/16), floor(z/16)
chunk_to_world:  Vector2i -> Vector3    # chunk 最小角（世界空间，米）
to_render(w) / to_world(r)：World 持 origin 的换算（仅渲染层用）
```

- 区块键 `Vector3i(x,0,z)` → `Vector2i`；约 30 处调用点 + minimap / tactical map / 飞行标记适配。
- `floori` 对负坐标即向下取整（GDScript 语义），负数区块天然正确——探针钉死（±64000 边界两格）。
- `chunk_to_world` 返回 `Vector3`（浮点米）而非 `Vector3i`：渲染层可直接用；逻辑层继续用整数坐标。

### 3.2 双环加载（已实施，D-064）

| 环 | 半径 | 内容 | 方块数据 | 碰撞 | 预算 |
|---|---|---|---|---|---|
| 高模 | ≤4 区块（64 m，9×9 = 81 块） | 全精度 Chunk + 逐面网格 | 是（~75 KB/块） | 是 | 徒步 10 ms/帧；飞行 8 ms/帧偏置窗 |
| 低模 | 4~16 区块（64~256 m，实测 79 组） | 高度图粗网格（4×4 区块合并 / 4 格采样 / 顶点色） | 否（噪声可再生） | 否 | 中心跨组时增量重建（实测 24 组 ≈150 ms） |

**半径由实测反推，不取原计划的 8**（`tmp/p2_bench` 在 1 m/格尺度下重测）：

| 量 | 实测值 | 说明 |
|---|---|---|
| 单块冷加载 | **41 ms**（生成 24 + 网格与碰撞 11 + 列表 0.2） | 邻块齐备时的快路径 |
| 单块「邻块缺失」保守全扫 | **143 ms** | 流式边界的常态，故新块入队必须邻近优先 |
| 环 2 / 4 / 5 / 8 冷填充 | 25 块 2.0 s / 81 块 **3.3 s** / 121 块 5.0 s / 289 块 **11.9 s** | |
| 徒步每跨一格区块的补充量 | 环 4 = 9 块 ≈ 0.37 s | 环 8 = 17 块 ≈ 0.7 s，配合「每帧至少 1 块」的时间预算，玩家会**长期停在 24 fps** |

结论：环 8 在当前单块成本下不可交付（不是「加载屏能盖住」的问题——走路时每跨一格都要补 17 块，帧率会持续塌陷）。环 4 把冷启动压到 3.3 s、跨格补充压到 0.37 s，视野由低模环补到 256 m——玩家感知到的「看得远」由低模提供，高模只负责**撞得到、挖得到**的 64 m。后续若把生成挪到 `WorkerThreadPool`，`LOAD_RADIUS` 可单常量上调。

- 卸载滞后沿用 `UNLOAD_PAD`；编辑块离开高模环时按现有 `_modified_data` 逻辑内存留存（世界不落盘，现状即如此）。
- **出生性能**：环 4 冷启动 81 块 ≈ 3.3 s → 「出生加载屏（`SpawnLoading`）+ bootstrap 预算（每帧 4 块、220 ms）」；环填满即回落常规预算，加载屏淡出。无头环境不建加载屏。
- **低模接缝**：采样步长 4 且组边界落在 16 的倍数上，区块边界必然落在采样网格上，故接缝线上低模与高模高度**逐点相等**（两边同读 `World.get_surface_height`）；探针钉 2312 个顶点误差 0 m。格内插值误差：平原 ≤1.5 m、全窗口最大 20 m（山区陡坡，`MAX_SLOPE=6` 时 4 m 采样必然丢细节，属预期取舍）。
- **draw call**：实测 93 高模块 + 79 低模组 ≈ 172 次绘制（不含发光面/碰撞体），比原估 650 低——因为环 4 而非环 8。真机仍需目检。

### 3.3 一格 = 一米的连锁尺度表

| 项 | 现（0.5 m/格） | 新（1 m/格） | 影响 |
|---|---|---|---|
| 跑道 | 112 格 = 56 m | 112 m | 起飞距离更宽裕 |
| 世界高 | 256 格 = 128 m | 256 m | 山更高，需复核飞机升限 |
| 最高山 | 188 格 = 94 m | 188 m | 巡航撞山风险↑；`MAX_SLOPE=6` 格 = 6 m/格，坡度比不变 |
| 飞机 | ~5 m 长（米制不变） | 不变 | 相对地形小一半、更「玩具感」；或飞机模型 ×2 保持「飞机占 10 格」观感（开放细节，默认不动） |
| 视野距离 | 32 m | 高模 64 m + 低模 256 m（D-064 实测反推，原计划 128 m 因单块 41 ms 不可行） | 沉浸感↑ |
| 单块生成耗时 | 23~29 ms | 同（格数不变） | — |

### 3.4 世界边界（已实施，D-064）

±64000 格。**软边界**：加载环在界外截断不生成（不产生区块键），海面/雾延伸到界，HUD 提示「已到世界边缘」——硬空气墙违反本作「全域无空气墙」的铁律（地形陡壁教训同款精神，MEMORY.md）。

实现要点：`World.is_chunk_in_bounds` 是唯一判据（区块 c 覆盖 `[c*16, c*16+15]`，故合法区间 `[-4000, 3999]`，负数侧多一格）；`_load_chunk` 与 `_rebuild_wanted` 两处入口都拦，`fill_ring_sync`/`ensure_chunks_in_region` 自然继承。玩家站位贴边时 wanted 只保留界内块（实测 63 块而非 81 块），界外一个键都不会造出来。提示走 `is_near_world_edge`（界内 512 格起）+ 状态变化才播报，不刷屏。

**大洋区域勘察**（±60000 均匀采样 234×234 点，`water` 策略 + 噪声岛礁天然成立，无需新地貌算法）：

| 区域 | 低于海平面 | 露出海面 | 结论 |
|---|---|---|---|
| 太平洋 | 84.1% | 15.9% | 128 km 大洋 + 成片岛礁 |
| 大西洋 | 75.4% | 24.6% | 同上 |
| 印度洋 | 77.5% | 22.5% | 同上 |
| 北极 | 100% | 0% | `iceberg` 策略封冻海面，冰盖在水面之上 |

## 4. 对现有系统的冲击面（实施时逐项过）

- **飞行**：尺度（§3.3）、流式窗口常量按米重核、指引/下滑道锚点若在界外需走 render 空间
- **小地图 / 战术地图 / 地球 UI**：采样走整数世界坐标（origin 无关），显示比例要覆盖 128 km
- **村庄 / 机场 builder**：固定坐标 + 平整保护区不变；与大世界/大洋的交互要验
- **竞速**：赛道坐标基准需确认（独立场景，预计无世界坐标依赖）
- **船 / 钓鱼 / 港口 builder**：世界锚定——纳入搬迁根
- **录制 / 回放**（flight_recorder/flight_replay）：位置序列的浮点/整数与 origin 语义要确认
- **任务锚点 / 飞行标记 / 导航目标**：同上
- **mob 生成**：按玩家周围，无坐标假设；生成半径与双环协调

## 6. 定夺结果（2026-10-21 用户答复）

1. **速度尺度 → A 保持现行**：横跨约 42 分钟（飞机）。不提速，飞行模型常量不动。
2. **世界结构 → A 每区域各 128 km**：保留地球选择器；大洋区域即「128 km 大洋 + 岛礁 + 冰山」（冰山噪声已存在，D-028）。
3. **低模实现 → A 高度图粗网格 + 合并**：4×4 格采样（4 m 分辨率）+ 4×4 区块合并；无碰撞、无方块数据、不渲染树/结构。
4. **实施范围 → A 全量 P0→P3 连续实施**：不做原型停顿，逐 Phase 交付。
