# 2026-10-12 开发日志：飞行器首期（feature_flight / D-031）

## 参考项目与范围裁剪

用户要求「新建 feature_flight 分支，参考
[JaredTate/tatertotsflightsim](https://github.com/JaredTate/tatertotsflightsim)
实现飞行」。参考项目是 Three.js + TypeScript 的浏览器飞行模拟器，`src/physics/
aircraft.ts` 是纯函数定步长 6 自由度积分，气动系数按 C172 / F-16 / A-10 / 747
四机型标定，另有襟翼/起落架/配平/失速尾旋/结构过载/武器等分支，体量巨大。
本作是儿童向体素世界，逐个移植既不现实也无必要，故「思路对齐、体量裁剪」。

网络抓取受限（WebFetch 对公众号与 GitHub 均返回空），改用 `curl` 经沙箱代理
直取 `raw.githubusercontent.com` / `api.github.com`，拿到 README 与
`src/physics/aircraft.ts` 原文，确认其 `step()` 纯函数切分值得照搬。

确认范围（用户三选一，全取推荐）：**可放置/乘坐的飞行器** +
**简化真实气动** + **首期不做武器**。

## 完成内容

三层分工，对齐参考项目「纯逻辑 step() + 表现层」：

- **`scripts/vehicles/aircraft_flight.gd`**（`AircraftFlight extends RefCounted`）
  ——纯逻辑气动，**不碰场景树**，探针可直接驱动断言。只保留四条可感知规律：
  ① 升力 = 动压 × 翼面积 × CL(α)，线性段斜率 CLα、越临界攻角失速掉升力；
  ② 诱导阻力随 CL² 增长；③ 空气密度随高度指数衰减（标高 8500 m）；
  ④ 操纵权限随动压衰减。**转弯不做额外公式**——升力垂直于速度且位于机体对称面
  内，压坡度自然把升力掰向侧向。
- **`scripts/vehicles/aircraft.gd`**（`Aircraft extends CharacterBody3D`）——
  只做「把状态搬进场景」：机身碰撞与地面支撑、轮胎抓地、撞击解体、乘员座位
  变换、信号广播。碰撞盒只包机身（2.2×1.6×5.2 m），**翼展不参与碰撞**。
- **`scripts/vehicles/aircraft_model.gd`**（`AircraftModel`）——纯代码生成的
  机模（机身/座舱/风挡/上单翼/副翼/尾翼/舵面/前三点起落架/螺旋桨），零外部资源。

接入：`ItemTypes.AIRCRAFT`（配方铁锭 4 + 木头 6 + 线 2，创造快捷栏有货），
手持右键身前平地放下；走近按 F 登机，W/S 油门、鼠标操纵杆（俯仰/滚转）、
A/D 方向舵、空格刹车、F 下机；驾驶期间玩家物理冻结、位置每帧贴座舱位、
追尾相机随姿态倾倒；HUD 飞行仪表（空速/高度/油门/失速告警）。解体抛出乘员
扣血，残骸 4 秒消散。

## 排错记录（探针逼出来的真缺陷）

写 `tests/flight_probe.gd`（A 段纯气动标定 + B~F 段世界里开高架跑道跑全链路）
过程中，探针把三个**真实缺陷**逼了出来，若只靠肉眼调试必然误判：

1. **俯仰符号反了（致命）**：`_integrate_attitude` 里 pitch 项多加了一个负号，
   于是「拉杆」变成压机头——飞机在跑道上永远抬不起前轮，之前那个看似「离地」
   的结果其实是**冲出跑道末端掉下去**。探针 C 段「滑跑 64.6 m」的异常距离
   是唯一的线索。修正：`Basis(Vector3(1,0,0), state.pitch_rate * delta)` 取正号。
2. **地面俯仰限位取错**：修正符号后，拉杆会把机头抬到 19° 卡在机轮上，攻角
   越过临界角、滑跑全程被标成「失速」。修正：地面改用机轮限位 `GROUND_PITCH_MAX`
   （12°）而非空中限位（83°）。
3. **配平载荷系数断言放错高度**：测试在 3000 m 处量「平飞载荷系数」，那里空气
   密度只剩 70%，读数自然只有 0.72。修正：改到**海平面**并按
   `CL_trim = mg/(q·S)` 反算配平攻角（3.5°），读数回到 1.00。

另有若干探针侧坑：`Vector2i` 上误访问 `.z`（应为 `.y`）；飞机中途自行解体
被 `queue_free` 导致 `previously freed`——重排段落，D/E 段改用独立空中飞机并
投到区块高度上限之上（全图无方块），F 段才做撞地；`use_player_input = false`
但 `piloted` 仍 false 会让油门每帧回零——封一个 `drive_remotely()` 入口；
跑道沿 +Z 铺但机头朝 −Z，一抬轮就冲出跑道进原始地形卡住——引入
`RUNWAY_HEADING := PI`。

**标定**（240 kg 短距起降机，ISA 海平面）：失速 13.1 m/s（47 km/h）、
抬轮离地约 14~16 m/s、半油门巡航 38 m/s、满油门平飞上限 50 m/s、VNE 55 m/s、
起飞滑跑约 18 m、L/Dmax ≈ 8。

## 驾驶舱核对与机模 ×3 放大（`ead7761`、`待提交`）

用户要求核对驾驶舱设计，取证截图 + 眼位读数把三处缺陷逼了出来：

1. **座舱视角不可达**：登机时 `camera_distance` 被强制为 `CAM_DISTANCE_MAX`，
   而滚轮分支又要求 `_aircraft == null`，且没有任何视角切换键——确认范围里
   写明的「第三人称跟随相机 + 座舱视角」实际只剩一半。修复：滚轮在驾驶中
   同样生效（拉近即座舱第一人称）。
2. **`_apply_camera_mode()` 会把飞行员重新显示出来**：`set_third_person(true)`
   直接 `visible = true`，覆盖了 `ride_aircraft` 里的 `_model.visible = false`；
   驾驶中任何触发相机刷新的路径（如今包括滚轮）都会让人物「站」在机身上。
   修复：`_apply_camera_mode` 末尾驾驶中强制隐藏模型与手持物。
3. **尺度不自洽（最关键）**：玩家身高 3.6 格，1:1 机模整机只有 2.28 格高
   （机身 0.86、座舱罩顶 0.995、垂尾顶 1.425）——坐进座位后眼位 1.85，
   **比全机最高点还高 0.425 格**，「坐进座舱」几何上不成立，第一人称实为
   「骑在机背」，画面正中是一根几乎齐眼的螺旋桨桨叶。经用户确认按
   `MODEL_SCALE = 3` 放大：翼展 24 格（12 m）、机长 17 格（8.5 m）、垂尾顶
   4.28 格（2.1 m），座舱罩顶 2.99 格、眼位 2.75 落进罩内，第一人称成为
   真座舱（风挡玻璃在前、机头与螺旋桨在前下方）。

连带调整（全部随 `MODEL_SCALE` 缩放，避免手算错）：

- 碰撞盒 `(2.2,1.6,5.2)×3`、中心 y `−0.05×3`，底面恰在 `−GROUND_CLEARANCE`；
- 座椅位改为显式 `(0, 1.35, −2.8)`——脚踩机舱地板、眼位落进座舱罩；
- 驾驶专用追尾参数：`CAM_DISTANCE_MAX_RIDING = 20`（9 格会被机身糊满屏）+
  `CHASE_PITCH_RIDING = −0.22`（抬高相机越过垂尾，否则追尾正对自己的尾翼），
  下机时弹簧臂俯仰恢复与第一人称相机一致；
- 下机落点从机身左侧 2.6 格改 5.0 格——跨出碰撞盒半宽 3.3，否则出生在
  机体碰撞盒内被挤出去；
- 风挡玻璃 alpha 0.55 → 0.35，座舱视角色罩不再糊脸；
- 探针起飞点不再重复加 `GROUND_CLEARANCE`（`place()` 内部会加）——1:1 时
  只是 0.95 m 的无害落差，×3 后落差 2.65 m、落地冲击 7.2 m/s 逼近
  `CRASH_IMPACT_DV = 7`，飞机落地即卡死不加速（本轮 5 项 FAIL 的根因）；
- 探针净空 5 格 → 9 格（垂尾顶在跑道面上 6.8 格）。

### 登机碰撞 bug 修复（真实游戏 bug）
登机时玩家被瞬移到座舱位，落在机体碰撞盒内部，与飞机两个 `CharacterBody3D` 互相深穿透；`move_and_slide` 把飞机弹飞、单帧速度损失 ≥ `CRASH_IMPACT_DV=7` 触发撞击解体——表现为「一登机就坠机」。修复：`player.ride_aircraft` 登机后 `add_collision_exception_with(craft)`，`exit_aircraft` 时 `remove_collision_exception_with(craft)`（Godot「坐在载具里」的标准做法）。

### 飞行仪表盘核对（#52，取证探针）
新增 `tests/flight_hud_shot.gd`（窗口运行）：驾驶飞机经「地面滑跑 → 空中巡航 → 失速告警」三态，每态截一张 HUD 入镜图，并把面板文案与 `Aircraft.snapshot()` 逐项比对——仪表与物理必须同源。

首轮 6 个 FAIL 全是**验证时序缺陷**，非逻辑 bug：

1. 滑跑态「空速含 40 km/h」——`snap` 是断油前旧快照，面板已实时显示断油后的 31 km/h；
2. 巡航 / 失速态 1 帧漂移（114vs115、176vs177）——快照比面板晚一帧；
3. 失速告警行在截图 3 帧等待中抖动消失。

修复：`_verify_panel` 改为**当场强制 `_hud._refresh_flight_panel()` 再取同帧 `snapshot()`**（二者同源自 `_state`），并把三阶段统一为「先验证、后截图」。复跑 `FLIGHT_HUD_DONE fails=0`。

附带修正油门仪表读数：`snapshot()` 原读 `state.throttle`（每物理帧由 `controls` 拷入，滞后一帧），油门条不跟手；改为直接读飞行员指令 `controls.throttle`，断油即显 0%。
