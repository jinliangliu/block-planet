# 2026-10-13 开发日志：探索模式重构（零件拼装 + 聚合气动，D-032 / Phase 0→1）

## 背景

用户重新定义探索模式玩法：**3D 体素风格 + 零件拼装 + 模拟飞行**，核心循环
「造飞机 → 试飞 → 做任务 → 赚资源 → 再改造」。飞机 = 多个零件拼装，每个零件
贡献 质量/升力/阻力/推力/耐久，外观为体素块。路线取「预设零件 + 体素外观」，
气动/质量/连接关系可控、性能好。

以此为准，首期 `feature_flight` 的「整机烘焙气动」需重构为「零件聚合推导」。

## Phase 0：决策定型（D-032）

- MVP 边界（用户划定）：小岛 + 一条跑道、一种固定翼、七种零件、建造（放置/
  旋转/对称/重心显示）、简化气动 + 辅助稳定、三任务（起飞/绕点/降落）、金币
  解锁零件、蓝图存取。
- 后置进 backlog：多人/联机、模组与创意工坊、太空/火箭、地图/任务编辑器、
  马赫/矢量推力、AI 交通、雷暴、云存档。
- 货币沿用绿宝石（MVP 不建平行经济），零件 `cost` 即绿宝石价。
- 分期：Phase 0 文档 → Phase 1 零件层 + 聚合气动 → Phase 2 建造编辑器 →
  Phase 3 试飞闭环 + 三任务 + 解锁 → Phase 4 打磨。

## Phase 1：零件层 + 聚合气动（最小可飞）

新增文件：
- `scripts/vehicles/part_data.gd`（`PartData extends Resource`）——零件模板：
  质量/材料/成本/耐久/尺寸 + 升力面面积 + 寄生阻力 + 推力/油耗 + 油箱容量 +
  控制 authority；`GRID_METERS = 0.5`（与 D-030 体素 0.5 m 化一致）。
- `scripts/vehicles/placed_part.gd`（`PlacedPart extends RefCounted`）——蓝图
  中一处放置（模板 + 锚格 + 旋转），`local_pos()` 折米制中心。
- `scripts/vehicles/part_registry.gd`（`PartRegistry`）——七种零件唯一定义 +
  `default_loadout()`。

重构：
- `scripts/vehicles/aircraft_flight.gd`：新增内嵌类 `Airframe`（mass / wing_area
  / thrust_max / vne / cd0 / induced_k / 重心 / 升力中心），由
  `Airframe.aggregate(零件)` 求和；翼型/大气/操控常量保持静态；姿态积分逻辑
  逐字保留。
- `scripts/vehicles/aircraft.gd`：新增 `from_loadout(parent, at, heading, parts)`
  装配入口（spawn 后用聚合结果覆盖默认气动框）。
- `tests/flight_probe.gd`：A 段改读 `default_airframe()`，新增 21 项聚合断言。

硬约束：默认套件聚合值 = 旧烘焙标定（Σ质量 240 / Σ翼面积 14 / Σ推力 1650 /
cd0 0.075），故重构后飞行动作逐帧不变——由探针双侧断言守护。

## Phase 3a：任务框架 + 三任务逻辑（已完成并提交）

新增文件：
- `scripts/vehicles/mission_data.gd`（`MissionData extends Resource`）：三任务类型
  `TAKEOFF/CIRCUIT/LANDING` + 数值参数（`params`：目标高度/最低速度/绕点半径/
  降落区半径/触速上限/停稳速度上限/奖励绿宝石）+ `default_missions()` 给出 MVP 三任务。
- `scripts/vehicles/mission_manager.gd`（`MissionManager extends RefCounted`）：纯逻辑、
  无节点依赖；外部每帧 `step(dt, telemetry)` 喂遥测，成功/失败/超时后一次性
  `mission_result(success, result)` 并锁定；`result` 含 reason/elapsed/score/reward/
  touchdown_vs/各点最近距离。评分按类型（起飞看耗时、绕点看精度、降落看触地柔和）。
- `tests/mission_probe.gd` + `tests/mission_probe.tscn`：合成遥测验收 9 场景，21 项全 PASS。

裁决口径：起飞须离地并达目标高度+最低速度；绕点须按序过完航点（水平半径判定）；
降落须先离地再软着陆（触速≤上限）并于区内停稳，否则硬着陆/滑出区判负；坠机与超时
一律失败。

踩坑：探针用 `extends SceneTree` + `_initialize()` 无法挂到 Node 场景根（报
"inherits from native type SceneTree"），改为 `extends Node` + `_ready()` +
`get_tree().quit()`（与 flight/build_probe 一致）。另：GDScript 4.6 闭包对捕获变量
重赋值不向外传递，探针改用共享字典持有结果。

## Phase 3b：试飞闭环（已完成并提交）

`Aircraft.from_loadout()` 改为接收 `Blueprint`：先 `add_child`（_ready 读到 `_blueprint`
→ 建零件体素外观），再 `place()` 落位，最后用 `blueprint.aggregate()` 覆盖气动框。默认
`spawn()` 仍走 ×3 代码机模，手感不变。

`_ready` 分支：有蓝图 → `_build_part_visuals()`（按零件 `size × GRID_METERS` 生成 BoxMesh、
按类别上色、以重心为原点居中）；否则建代码机模。体素外观纯视觉、无碰撞。

验证（全绿）：flight_probe 新增 G 段——默认套件蓝图造机，体素外观块数 = 零件数（7/7）、
初始停在跑道、满油门可离地（第 276 帧，飞行特性与默认机一致）；A 段新增「default_loadout
聚合 = 默认气动框」闭环一致性。回归：smoke/life/build/mission 全 OK、flight_hud_shot fails=0。

踩坑：探针 G 段首帧 `is_on_floor()` 尚未被 move_and_slide 置真（spawn 当帧），误判离地；

## Phase 3c：绿宝石解锁新零件（已完成并提交）

`PartRegistry` 新增 2 个进阶零件（仅进 `all()`，不进 default_loadout）：`turbine`
（涡轮发动机，推力 2600 > 默认 1650，价 30）、`long_wing`（长航程机翼，升力面 18 >
默认 12，价 20）。

新增 `PartUnlocks`（RefCounted）：默认套件零件开局解锁，其余需花绿宝石；`purchase(id,
emeralds)` 余额充足则解锁并扣费、`reward_to_balance()` 并入任务奖励。余额由调用方持有
（真实游戏即玩家绿宝石库存），本类纯逻辑、易验。货币复用绿宝石(204)，不建平行经济。

验证（全绿）：unlock_probe 31 项全 PASS（UNLOCK_PROBE_OK）。回归：flight_probe OK
（默认聚合未受新零件影响）、build_probe OK。

至此 MVP 核心循环「建造 → 试飞 → 任务 → 奖励 → 改造」闭环：Phase 2 建造数据 +
Phase 3b 蓝图 spawn + Phase 3a 任务出奖励 + Phase 3c 奖励解锁新零件。解锁状态接入建造
编辑器零件面板（UI）留待编辑器交互期。

## Phase 4a：工坊台建造界面（build_screen）

新增 `scripts/ui/build_screen.gd`（BuildScreen extends Control）：模态建造界面——SubViewport
3D 预览（平台网格 + 零件盒 + CG 可视化）、轨道相机、零件面板（7 默认 + 2 进阶含购买）、

F 键试飞（经 from_loadout 生成并登机）。

接线：`Player.input_locked`（模态冻结输入）、`InputActions.toggle_build`（V 键）、
`Main` 实例化并处理 `flight_requested(blueprint)` → `Aircraft.from_loadout`。

验证中修复两个真实缺陷：
1. `PlacedPart` 无镜像链接，旋转后 `remove_at/rotate_at` 的 `_mirror_anchor` 重算失效
   （span 随 rot 变）→ 放置时显式记录 `mirror_link`，Blueprint 序列化同步持久化；
   build_probe 增补「旋转后带镜像删除一次移除 2 件」断言守护。
2. BuildScreen 继承 Control 后默认 visible=true，`open()` 守卫早退 → `_ready` 置 false
   （否则真实游戏界面常驻遮挡全屏）。

验证（全绿）：build_screen_probe 26 项 PASS（BUILD_SCREEN_PROBE_OK）；build_probe /
mission_probe / unlock_probe / smoke_test / life_probe / flight_probe 全 OK；
flight_hud_shot（窗口）fails=0。
