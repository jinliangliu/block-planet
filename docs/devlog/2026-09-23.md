## 三、运行时验证闭环（Godot v4.6.3 首次接入）

建立可复跑的验证流水线：

```
全量 --check-only  →  --headless --import（重建全局类缓存，注册 15 个全局类）  →  smoke_test
```

**过程中修复**：`ItemTypes.is_tool` 与 `Script` 基类的内置 `is_tool()`（0 参数）撞名，运行时报 `Expected 0 argument(s)` → 改名 `is_tool_item`，同步 5 文件 9 处。

**结果**：冒烟测试 **10/10 PASS**（含卸载重载留存、模式切换/飞行信号、合成预检），`SMOKE_TEST_OK`，EXIT 0。

**经验**：

- `--check-only` 独立编译模式**不注册 Autoload**——`GameState`/`Events` 报 not found 是假阳性。
- 新脚本必须先 `--import` 再 `check-only`，否则全局类缓存缺失报 not declared。
- PowerShell 工具 stdout 不回显，Godot 输出需 `2>&1 | Out-File -Encoding utf8` 落盘后读。

## 四、实机显示缺陷 W-01 ~ W-03（用户截图触发）

用户实机截图显示「规律三角网格 + 画面昏暗」。三轮取证（无头物理探针 → 绕向微测试 → 实机渲染截图）定位并修复：

| 编号 | 问题 | 修复 |
|------|------|------|
| W-01 | **绕向错误**：均匀索引 `(0,1,2)(0,2,3)` 使每个 quad 的两个三角形一正一背，`ConcavePolygonShape3D` 默认背面不碰撞 → 玩家穿透地表 | `chunk.gd._append_quad_indices` 按面方向分支选绕向（`+dir` 用 `(0,1,3)(0,3,2)`，`−dir` 用 `(0,2,3)(0,3,1)`），渲染与碰撞共用 |
| W-02 | 出生点高度取样列错位 + 1.2 m 悬空偏移，导致玩家嵌进头顶悬垂叶 | 出生列按真实方块扫描「两格空气 + 实心底」，双脚精确落顶面 |
| W-03 | 无 `WorldEnvironment`，清晨/夜间全黑 | 加 Environment（天空蓝背景 + 环境光 0.6） |

**关键经验（Godot 4.6 实证）**：trimesh 正面判定与叉积直觉**相反**——同角点序下顶面只有半数可碰撞。已写入代码注释。

**新增验证资产**：`tests/physics_probe`（四象限绕向微测试 + 落地复检）、`tests/render_probe`（实机截屏取证）。终态：玩家 `(8.5, 37, 8.5)` `on_floor=true`，截图视觉正常。

## 七、金字塔堆叠验证

用**真实 `_place_target()` 射线链路**（非 `set_block` 作弊）搭建 3 层、底 5×5、共 35 块的金字塔，验证砖块堆叠实现。

**结果**：`PYRAMID_TEST_OK placed=35`，**12/12 PASS**，exit 0。

- 结构：35/35 无空洞、无越界、层数精确
- 碰撞：塔顶射线命中 `y=37` 精确、塔外命中原始地面 `y=34` 无杂散
- 留存：区块卸载重载后 35/35 块仍在（`_modified_data` 生效）

**沉淀「射线脱靶五定律」**（调试同类问题通用）：

1. 相机须在空气格内，埋入实心必脱靶
2. 玩家物理须冻结，否则 `move_and_slide` 会拖走瞬移位
3. `looking_at()` 对正下方与 UP 共线退化，须手工构造 basis
4. 玩家胶囊会遮挡自上而下的射线（命中胶囊顶而非地面）
5. 同列上方已有方块时，高处射线先命中高处方块

## 十、防卡死保护与区块加载提速

- `player.gd._check_stuck()`：脚格 + 头格双实心且持续 ≥3 物理帧 → `_force_unstuck()` 瞬间清血 → 重生脱困。不走 `_damage`（图腾救活仍卡死会成死循环，创造无敌也需脱困）
- `_safe_respawn_position()`：重生点被堵时沿 Y 上扫「两格空气 + 实心底」落点
- `world.gd`：每帧加载 1 → 2 个区块，加载队列按距玩家的曼哈顿距离升序（脚下/前进方向优先）

**顺带修复真实缺陷**：`_respawn` 原先不重置 `_fall_speed`——重生前的残留下落速度在落地瞬间被误判为跌落伤害扣血。

**结果**：新建 `stuck_probe` **9/9 PASS**。
