## WF15 面向儿童的指令性文案必须有「按提示操作后能达成该动作」的端到端验收

**判据**：面向儿童的**指令性文案**（如「掉头」「左转」「把准星套进十字」等提示玩家去做某个动作的文案）必须有「**按提示操作后能达成该动作**」的**端到端验收项**，**不得只断言字符串相等**。

- 字符串相等断言（如 `assert(label_text() == "掉头")`）只证明「文案被输出」，不证明「儿童按提示操作后真的能掉头」。这是 **WF15 类验证假象**：探针全绿与用户投诉可以长期共存。
- 验收项必须贯穿「文案 → 输入 → 控制量 → 气动 / 状态积分 → 画面 / 机头朝向变化」全链路，并对 6-12 岁儿童的可操作性（短按力度、反馈可见性）负责，而非只验单侧函数返回值。
- 判据约束与落实见 ADR **D-098** §4（根因链）/ §5（引导层 + 一键自动飞回）/ §8（验证状态）。

### 触发该判据的事故案例：本次「掉头」（2026-11-15）

- `flight_director.gd:label_text()` 在 `absf(_dev_h) > 150°` 输出状态词「掉头」，但**不写 `controls`、不绑输入、不自动转向**；`tests/flight_director_probe.gd:222` 长期只断言字符串相等，没有任何「6-12 岁儿童看到『掉头』后能否真的掉头」的端到端验收。
- 叠加 `MAX_OFF = 120 / GAIN_PX_PER_DEG = 11` 饱和约 `10.9°`（`150° → 10.9°` 约 `139°` 全程十字零位移）与 D-090 `CRUISE_FADE_DIST = 800` 把十字 / 原标签淡到 `alpha 0.3` ⇒ **反馈真空**；D-096 `KB_ROLL_RAMP 4.0/s` + `RATE_RESPONSE 4.5` + PARTIAL 辅助松杆摆平 ⇒ 短按净航向只改约 `1~3°`、转 `180°` 需 `7~18 s`。**「照提示做」在物理上达不成该动作**。
- 用户反馈「提示掉头但画面不转」，裁决「一键完全自动飞回」（D-098）。修复方向：保留 `label_text()` 返回值逐字不变，在现有 `_fd._draw()` 内新增引导层（方向箭头 / 剩余角度 / 进度）+ 闭环自动驾驶；按 WF15 以端到端探针 / 真机目检（见 `docs/device-visual-checklist.md` **K 组 K1 / K2**）验收「按提示操作后能达成该动作」。
- **状态（2026-11-16 更新）**：上述「掉头」案例的端到端链路已由 `return_autopilot_probe` 单支引擎实测（首跑 77 PASS / 3 FAIL → 修复后 89 PASS / 0 FAIL，见下方案例）；整轮 full 档 77 支已实测 3067 PASS / 0 FAIL、8 段零 DIFF，真机目检仍「待真机目检」。

### 2026-11-16 引擎实测追加案例：比例闭环在 ±180° 奇异点失效

- **静态自洽 ≠ 运行时正确**：`return_autopilot.gd` 首版「目标坡度 ∝ 带符号 `nav_dev`」的比例闭环在纸面上自洽，但 `nav_dev` 经 `wrapf` 在 ±180° 掉头工况从 `+170.00` 跳到 `−173.50`，目标坡度随之从 `+25°` 翻成 `−25°`，坡度 `−31° ↔ +19°` 来回摆 ⇒ 自动驾驶组净转向 `13.47°`，仅比对照组 `12.34°` 多 `1.13°`。**任何「按提示操作后能达成该动作」的闭环都必须把角度奇异点 / 边界工况列为构造式验收项**，不能只验常规区间。
- **物理假设必须实测证伪，不能直接当判据**：反向对照 C8b 原写「对照组机头基本不变」，实测 `[R-end] turned=12.34°`（无自动驾驶也自然飘转），该假设被证伪 ⇒ 判据改为「自动驾驶组转向幅度显著大于对照组 ≥+3°」。**「对照组应当不动」这类未经实测的物理直觉，不得直接写成验收闸**；先打印实测值取证（本例 `_trace`），再定判据。
- 修复（方向迟滞锁 `TURN_LATCH_DEG = 150` / `TURN_RELEASE_DEG = 110` + `reset()`）后单支重跑 **89 PASS / 0 FAIL**，`turned=41.09°` vs 对照组 `12.35°`。详见 ADR D-098 §4 / §5 / §8；整轮 full 档 77 支已实测 3067 PASS / 0 FAIL、8 段零 DIFF。
