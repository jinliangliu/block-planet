# 性能优化报告（D-038，2026-10-17）

**结论先行**：帧时间不是瓶颈，CPU 尖峰是。五项热点全部量化后改造，最大尖峰（挖/放方块触发的区块重建）**19.5 → 5.5 ms**，机场建造 **1756 → 559 ms（3.1×）**；顺带修复一个 D-035 遗留的真 bug（世界边缘破洞）。全部 28 个探针 0 FAIL，几何输出与优化前逐行一致，user:// 逐字节还原。

## 测量环境与方法

Intel Iris Xe / 1280×720 / Forward+ Mobile 渲染器。一次性探针 `tmp/perf_probe.gd` 逐热点分段计时；`tmp/chunk_mesh_baseline.tscn` 做几何等价性硬验收；`git stash` 切换原始代码取「前」值。

**帧时间结论**：沙箱显示器 vsync 上限 ≈33 FPS——隐藏全部 UI 与世界、CPU 仅 0.03 ms 时帧时间仍 30.4 ms。关 vsync 后完整场景 **1.48 ms/帧**（240 draw calls / 12 万三角形）。**渲染不是瓶颈，优化目标是 CPU 侧尖峰（hitch）**。

## 核心机制

1. **网格重建按列收窄**：面遍历按列限定 y 范围——上界取列顶（`col_top`），下界取本列与四邻列最高不透明格再 −1；该高度以下六面皆被遮。每列的可信度单独记录、单独失效（地下开挖只作废该列及其四邻列），`pristine` 门控全部移除。
2. **`col_verified` 连续实心段推理**：正确性前提「列地以下全实心」不能由「编辑点 ≥ 列地」推出——村庄整平在谷地上方铺的悬浮层（列地 35 但 23~31 是空气）曾打穿该规则，实测丢 4560 个顶点。改为按「自底向上连续实心段」维护与推理（`valid = ground ≤ verified + 1`）。
3. **存档防抖**：notify 只置脏位，1.5 s 节流落盘；领奖（claim）与退出仍立即落盘。
4. **结构生成三段式**：预加载只落数据不建网格 → 批量写入跳过逐列维护 → 邻居齐备后统一重建一遍终态。生成期（树木/水草）同样走批量。

## 顺带修复的真 bug（D-035 重构事故）

卸载区块后给四邻入队「补面重建」的排泄循环，在初始提交里本位于 `_update_chunks` 末尾，后来提取 `_load_priority` 函数时被甩到其 `return` 之后，成为**永不执行的死代码**——走出加载范围时，已载区块的世界边界永不补面（边缘破洞）。本轮归位（每帧至多 2 个、首个不限预算保证推进）+ 入队去重，并新增 `tests/rebuild_drain_probe` 可观测断言：卸载 E → X 入队 → 队列排空 → X 边界出面 **1728 → 3684**。

## 遗留（后续方向，非本轮范围）

- 重建剩余的 ~5 ms 是 GDScript 逐面成本（每面 6 邻居查询 + 4 顶点 + 6 索引 ≈1.8 μs）；再往下需增量网格或线程化（开放问题 O-2）。
- 机场建造剩余 559 ms 是首帧前的一次性成本（无运行期卡顿）；继续压需把统一重建也分帧，前提是保证出生点碰撞就绪。
- `top_block_at` 保留 `pristine` 门控：恢复区块首次被编辑后其余列是「未知」编码，放宽会越界。
- 村庄建造与机场同机制但未单独计时（预估同样量级收益）。
